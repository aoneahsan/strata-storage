# strata-storage — package inventory

The fixed-path record of every dependency this repository declares, what it is for, and every deliberate
version pin. Keep it accurate on **every** add, remove or upgrade — an inventory that lags the manifest is
worse than none.

**Last Updated:** 2026-07-25

---

## package.json units

One unit is published; the other two never are.

| Unit | Path | Published? |
|---|---|---|
| `strata-storage` | `package.json` | ✅ the package |
| `strata-storage-demo` | `example-apps/demo-app/package.json` | ❌ local demo app, excluded from `files` |
| *(module marker)* | `dist/package.json` | ships inside the tarball, but declares **no name and no version** — see the note below |

> 🔴 **`dist/package.json` must never regain `name` or `version`.** A second manifest declaring
> `name: "strata-storage"` makes `cd dist && npm publish` succeed and ship the wrong tree under the real
> package name. That is the structural cause of the 2.8.2 incident. It is generated by
> `scripts/build.js` as exactly `{ "type": "module", "sideEffects": false }`; resolution is governed by
> the root manifest's `exports` map alone.

## Runtime dependencies

**None.** This is the package's headline property and a constraint on every change: the core is pure
TypeScript. Anything a consumer's app already owns is a peer, not a dependency.

## Deliberate version pins

| Pin | Reason | Revisit when |
|---|---|---|
| `typescript ^6.0.3` | TypeScript 7 is the native compiler and ships no JS API, which breaks `typescript-eslint` (its parser crashes at load) and any tool that calls the compiler API. The fleet-wide blocker is recorded in `~/.claude/rules/package-version-known-issues.md` on the owner's machines. | `@typescript-eslint/typescript-estree` publishes a peer range allowing `typescript >= 7`. |
| `zone.js ~0.16.2` | Angular pins its own zone.js minor; a wider range resolves to a version Angular rejects. | The Angular dev dependency moves to a major that pins a different zone.js line. |
| `engines.node >=24.13.0` | Matches `.nvmrc`. The package is ESM-only, and this is the Node line where `require()` of an ESM graph works. **Raising this is a major** — it can break installs for consumers who changed nothing. | Only alongside a major release. |

## Packages deliberately absent

| Not used | Instead |
|---|---|
| Any runtime dependency | Pure TypeScript — the zero-dependency guarantee. |
| A SQLite plugin | The native SQLite adapter is hand-rolled against the platform SDKs. |
| A filesystem plugin | The native filesystem adapter uses `FileManager` (iOS) and `java.io.File` (Android). |
| A bundler (rollup, tsup, esbuild) | `scripts/build.js` drives `tsc` directly and rewrites path aliases. |
| A test runner (Vitest, Jest) | Typecheck, lint and build are the gates — a documented project decision. |
| `.npmignore` | `files` in `package.json` is the allowlist. A denylist ships whatever it forgot to name. |

## Verifying this file

```bash
# every declared dependency, from the manifest itself
node -e 'const p=require("./package.json");for(const k of ["dependencies","peerDependencies","devDependencies"])console.log("\n"+k+":"),console.table(p[k]||{})'

# one manifest per package name — two entries sharing a name is a stop-the-line finding
find . -name package.json -not -path '*/node_modules/*' \
  -exec node -e 'const d=require(process.argv[1]);console.log((d.name||"<marker>"),d.version||"",process.argv[1])' {} \;

# the gates
yarn typecheck && yarn lint && yarn build
```
